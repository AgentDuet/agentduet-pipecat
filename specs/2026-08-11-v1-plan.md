# pipecat-agentduet v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the v1 milestone per [specs/pipecat-transport-spec.md](pipecat-transport-spec.md) §11: outbound dialing (which activates the full §6 event surface), the two §9 examples (native showcase + multi-modal), and quickstart docs — on top of the merged inbound spike.

**Architecture:** `_AgentDuetSession` becomes direction-aware: it detects an outbound-dial shell by `call.caller.value == call.subscriber` — the **same public predicate `remote_party` already uses** (on a `make_call` shell the SDK sets `caller=subscriber`; on an `IncomingCallNotification` attach it sets `caller=participant.value`). Call *state* cannot discriminate: every `Call` constructs in `NEW` (verified, see facts below). The session picks the dial-in or dial-out event-name triple at construction, and on outbound `start()` spawns `call.dial()` as a self-resolving asyncio task instead of awaiting it (spec §5: dial blocks up to `ring_time_seconds`, so awaiting inline would stall pipeline startup). All teardown-matrix invariants and the `_teardown()` choke point are unchanged. The transport halves need **zero changes** — direction lives entirely in the session.

**Known limitation of the predicate (documented, not fixed here):** an `OutgoingCallNotification` attach (the subscriber placed a call outside the SDK — the copilot/desk-phone shape, an explicit v1 non-goal) also has `caller == subscriber` but must be *answered*, not dialed. Constructing a transport on one misdetects it as dial-out; `dial()` then raises `CallStateError` (its `_origin` is `"incoming"`), which the establish path maps to a clean `on_dialout_error` + worker cancel — a clean failure, not a hang. The durable fix is a public `origin`/`is_outbound` property on the SDK's `Call` (today direction lives only in the private `_origin`, which this package must not read); file that as an SDK feature request during Task 2 and adopt it when released.

**Tech Stack:** Python ≥3.12, uv, `agentduet>=1.0.0b10`, `pipecat-ai>=1.7,<2`, pytest + pytest-asyncio + pytest-timeout, ruff.

**Verified API facts (checked against installed `pipecat-ai` 1.7.0 and the `agentduet` 1.0.0b10 checkout at `~/Documents/wss-sdk-python`; do not re-derive):**

- The spike plan's verified facts ([2026-08-03-agentduet-transport-spike-plan.md](2026-08-03-agentduet-transport-spike-plan.md) header) all still hold; they are not repeated here.
- `Session.make_call(dest: Address) -> Call` mints an outbound shell: `state == CallState.NEW`, `_origin="outgoing"`, `caller == subscriber`, `callee == dest.value`, `participant == dest`. No SIP placed yet.
- **Call state does NOT carry direction.** `Call.__init__` sets `state = CallState.NEW` unconditionally, and `Session.process_call` (both notification types) never changes it — an inbound call at transport-construction time is also `NEW`. `RINGING` is set in exactly one place in the SDK: inside `dial()`, mid-command, outbound only. The only construction-time direction signals are the private `_origin` (off-limits) and the caller/subscriber relationship (used here). The spike's `FakeCall` mismodeled inbound as `state = RINGING`; Task 1 fixes that fidelity bug so no test can lean on it.
- On a **falsy** `dial()` (`CALL_UNANSWERED`/`TIMEOUT`), the SDK runs `_force_close()`, which closes the voice WS; the voice layer synthesizes a transport-drop HANGUP that fires `on_hangup` handlers (exactly once — `close()`'s docstring states this contract). So a failed dial fires `on_hangup` too, racing `dial()`'s falsy return: the worker-cancel reason may be `"dial failed"` or `"remote hangup"` depending on which lands first. Tests must pin the invariants (error event fired, exactly one cancel, no connected/disconnect events), not the racy reason string.
- `Call.dial(*, ring_time_seconds: int = 60) -> CommandResult` — **blocking** until answered or failed; truthy on answer; falsy with `error_code in {"CALL_UNANSWERED", "TIMEOUT"}` on failure (on falsy it force-closes the voice WS itself). Raises `ValueError` outside 1–120, `CallStateError` if not an outbound call in `NEW`, `CallClosedError` if the call terminated mid-flight, `CallError` if the voice WS could not open. There is no separate "answered" event; answered is the resolution of `dial()`.
- **Exception hierarchy:** `CallClosedError` and `CallStateError` both subclass `CallError`. A hangup landing between task spawn and `dial()`'s state check surfaces as `CallStateError` (state is `TERMINATED`, not `NEW`), *not* `CallClosedError` — so the establish path must catch `CallError` broadly and check `call.state` to pick the payload.
- `call.send_audio()` has no LIVE-state guard: pre-answer sends buffer into the ring buffer (only `TERMINATED` raises `CallClosedError`). No output-transport guard needed for the pre-answer window.
- Outbound remote party: **confirmed by the spike's live probe** — the callee track carries the remote audio; the session's existing subscriber-derived `remote_party` rule is correct in both directions unchanged.
- Messaging: `@sm.on_incoming_message` delivers `IncomingMessage(id, subscriber, participant: Address, payload: dict)`; `session.send_message(SendWAMessage(api_version=..., data=...)) -> SendMessageResult` (`success`, `error_code`, `error_content`).
- Pipecat 1.7 showcase services (import paths verified importable): `pipecat.services.deepgram.stt.DeepgramSTTService` (needs the `pipecat-ai[deepgram]` extra), `pipecat.services.openai.llm.OpenAILLMService`, `pipecat.services.cartesia.tts.CartesiaTTSService`, `pipecat.processors.aggregators.llm_context.LLMContext`, `pipecat.processors.aggregators.llm_response_universal.LLMContextAggregatorPair`. **Verify constructor signatures against the installed package when writing Task 7** — only the class names were inventoried.

**Deliberate scope choices:**

- `ring_time_seconds` is a constructor kwarg on `AgentDuetTransport` (validated eagerly, 1–120). It is a *dial parameter*, not audio configuration, so it does not violate the zero-audio-config rule. Validated in the constructor because the SDK's own `ValueError` would otherwise fire inside a spawned task after pipeline start.
- One deliberate behavior change to the inbound path: `answer()` raising `CallError` (voice WS failure) is now caught and reported via `on_dialin_error` + worker cancel, where before it propagated out of `input.start()` and crashed the pipeline. Same failure, cleaner teardown; covered by a new test.
- `on_call_state_updated` fires at the same two points as inbound (connected, teardown). `RINGING` during dial is set inside the SDK's `dial()` with no observation hook; the parent spec §6 already omits ringing events deliberately.
- No `AgentDuetTransport.from_notification` sugar (spec calls it "sugar, not architecture" — YAGNI), no `bot(runner_args)`, no DTMF/recording/copilot (spec non-goals).
- The keyless `examples/inbound_tone_bot.py` from the spike **stays** as the zero-key smoke test; v1 adds the two spec §9 examples plus a keyless outbound tone bot as the dial path's live-validation vehicle.

Replace the body of `start()` and factor `_establish()`:

```python
    async def start(self) -> None:
        """Establish the call: answer (inbound) or dial (outbound).

        Latched: the first caller establishes, later callers wait for start to
        complete. Inbound answer is awaited inline (fast, 10 s command timeout);
        outbound dial is spawned as a task because dial() blocks until answered
        or failed (up to ring_time_seconds) and must not stall pipeline startup
        (parent spec §5). "Answered" is the resolution of that task.
        """
        if self._start_begun:
            await self._start_complete.wait()
            return
        self._start_begun = True
        try:
            # Hangup can arrive in any state, including mid-answer/mid-dial:
            # register the handler before establishing so the window is closed.
            self._call.on_hangup(self._on_hangup)
            if self._call.state == CallState.TERMINATED:
                await self._fail_start(_terminated_result())
                return
            if self._outbound:
                self._establish_task = asyncio.create_task(self._establish())
                # _establish handles every SDK-contract exception itself; this
                # backstop only surfaces genuinely unexpected bugs, which would
                # otherwise hide until GC logs "exception was never retrieved".
                self._establish_task.add_done_callback(self._log_establish_crash)
            else:
                await self._establish()
        finally:
            self._start_complete.set()

    @staticmethod
    def _log_establish_crash(task: asyncio.Task) -> None:
        if not task.cancelled() and task.exception() is not None:
            logger.exception("dial task crashed", exc_info=task.exception())

    async def _establish(self) -> None:
        """Answer or dial, then fire connected events on a truthy result with
        no teardown racing it. Self-resolving on every path: a hangup or close
        mid-flight aborts the SDK command with CallClosedError/CallStateError,
        so this task never needs external cancellation."""
        try:
            if self._outbound:
                result = await self._call.dial(
                    ring_time_seconds=self._ring_time_seconds
                )
            else:
                result = await self._call.answer()
        except CallClosedError:
            await self._fail_start(_terminated_result())
            return
        except CallError as e:
            # Covers CallStateError too (a hangup landing between task spawn
            # and dial()'s state check surfaces as CallStateError, not
            # CallClosedError) and voice-WS open failures on either path.
            if self._call.state == CallState.TERMINATED:
                await self._fail_start(_terminated_result())
            else:
                await self._fail_start(
                    CommandResult(
                        success=False, error_code="CALL_ERROR", error_message=str(e)
                    )
                )
            return
        if not result:
            await self._fail_start(result)
            return
        if self._torn_down or self._call.state == CallState.TERMINATED:
            # A hangup raced the truthy result; teardown ran (or will run)
            # from on_hangup. Connected events must never fire.
            # Deliberate silence (spec matrix row 4): the hangup path owns
            # all signaling for this call.
            return
        self._connected_fired = True
        await self._notifier._fire(self._connected_event, self._payload())
        await self._fire_state()
```

Also update `_fail_start`'s debug log line to not say "answer" unconditionally:
